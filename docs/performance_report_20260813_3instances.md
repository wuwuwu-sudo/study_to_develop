## 7. 性能瓶颈与优化建议

1. **CPU 饱和（首要）**：8 逻辑核跑 3×8=24 worker 线程，%wait ~38%。三实例扩展受 CPU 总数限制。
   - 建议：`server.thread_pool_size` 与核数匹配（当前 8×3 > 8 核），或绑核/调低；多核机器上三实例才体现线性扩展。

2. **系统态过高（%system ~71%）**：网络收发 + **日志格式化**（`strftime` / `ostream`，perf 已确认）。
   - 建议：缓存格式化后的时间戳、降低日志级别、或合并日志写入（已有异步批量，仍可优化）。

3. **静态文件 send_file 同步读**：静态页 QPS（59k）低于 API。
   - 建议：sendfile 零拷贝 / 预读。

4. **本地缓存锁**：`LocalCache` 短锁乒乓仍是已知瓶颈（分片锁可缓解）。

5. **客户端瓶颈**：wrk 与服务器同机，高并发（合计 24k+）时本机 1.4Gi 内存导致 timeout，建议分布到独立压测机或提升内存。

## 9. 复现方法

      config/instance_${p}.json > /tmp/bench_instances/instance_${p}.json
