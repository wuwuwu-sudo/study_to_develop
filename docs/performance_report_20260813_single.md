## 7. 性能瓶颈与优化建议

1. **系统态过高（%system ~164%）**：网络收发 + **日志格式化**（`strftime` / `ostream`，perf 已确认）。
   - 建议：缓存格式化后的时间戳、降低日志级别、合并日志写入。

2. **静态文件 send_file 同步读**：静态页 QPS（~72k）低于 `/api/shops`（~76k）。
   - 建议：sendfile 零拷贝 / 预读。

3. **本地缓存锁**：`LocalCache` 短锁乒乓仍是已知瓶颈（分片锁可缓解）。

4. **客户端瓶颈**：wrk 与服务器同机，高并发（8k+）时本机 1.4Gi 内存导致 timeout，建议独立压测机。

5. **CPU 余量**：单实例仅用 ~3.7/8 核，多核余量正好用于多实例扩展（见 §8 对比）。

## 8. 与三实例报告对比（2026-08-13 同日同配置）

- 静态页 / `/api/dishes` 三实例甚至略低于单实例峰值，同样因 CPU 争抢（单实例独占时更能榨干单核流水线）。
- 在更多核 / 独立压测机下，三实例可进一步逼近线性扩展。
