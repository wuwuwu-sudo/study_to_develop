## 7. 性能瓶颈与优化建议（当前版本）

1. **CPU 饱和（首要）**：8 逻辑核跑 3×8=24 worker 线程，%wait ~39%。
   - 建议：`server.thread_pool_size` 与核数匹配（三实例建议 3-5），或绑核；多核机器上三实例才体现线性扩展。

2. **系统态仍高（%system ~74%）**：网络 `recv/send` + 日志落盘。
   - 建议：异步日志已实现；可进一步批量/降级；配合 Nginx `sendfile`/`open_file_cache`（已部署生效）。

3. **内存分配/释放（perf 实测 ~25%）**：每请求 `new`/`free`。
   - 建议：连接/响应缓冲池复用、`string::reserve`（下一步收益最大）。

4. **WAL 模式验证**：本次读路径未触发写争用；建议补充下单/改状态写路径压测验证 SQLITE_BUSY 缓解。

## 9. 复现方法

```bash
# 1. 生成高限流配置并启动三实例（建议 stdout 重定向 /dev/null，避免日志写满磁盘）

for p in 8081 8082 8083; do
  sed 's/server.rate_limit.max_requests=100/server.rate_limit.max_requests=10000000/' \
      config/instance_${p}.json > /tmp/bench_instances/instance_${p}.json
  nohup ./webserver --port $p --config /tmp/bench_instances/instance_${p}.json > /dev/null 2>&1 &
done

# 2. 三实例并行压测（汇总脚本）
python3 tools/bench_3instances.py "/api/shops" 8 4 "1,8,16,32,64,128"
```
