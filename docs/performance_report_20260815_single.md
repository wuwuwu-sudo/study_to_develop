## 7. 性能瓶颈与优化建议（当前版本）

1. **内存分配/释放已升至首位（perf 实测 ~25%）**：`operator new`/`malloc`/`cfree`/`_int_*`。
   - 建议：连接/响应缓冲池复用、`string::reserve`、减少每请求 `new`（下一步收益最大的方向）。

2. **系统态仍高（%system ~165%）**：网络 `recv/send` + 日志落盘。
   - 建议：异步日志已实现；可进一步批量/降低级别；网络侧配合 Nginx `sendfile`/`open_file_cache`（已部署生效）。

3. **锁（~9.5%）**：分片锁已降 LocalCache 争用，剩余来自线程池（`enqueue`/`cond_signal`）与连接表。
   - 建议：线程池批量唤醒；`server.thread_pool_size` 与核数匹配（三实例时 8×3>8 核）。

4. **响应序列化 `serialize`（8.4%）**：每请求整串拼接拷贝。
   - 建议：`writev` 拆分发送 / 连接级缓冲复用。
