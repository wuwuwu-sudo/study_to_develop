# webserver 三实例性能测试报告（2026-08-17 · tp=3 复测）

- **测试日期**：2026-08-17
- **工具**：wrk 4.2.0（~/.local/bin）+ pidstat / procfs（RSS/fd）+ redis-cli
- **服务器版本**：release 构建（C++17, epoll + **3 线程线程池 ×3 实例** + SQLite 连接池 16×3 + WAL）

- **压测目标**：三实例合计 QPS、响应延迟、最大并发连接数、资源消耗、长时间稳定性、缓存分层
- **本次为 tp=3 复测**（线程池 8→3，对应 §7 建议）：吞吐全面大幅提升、%wait 下降、稳定性更佳，详见 §8 对比

## 7. 性能瓶颈与优化建议（当前版本，tp=3）

1. **CPU 饱和（首要）**：8 逻辑核跑 3×3=9 worker 线程，%wait ~34.9%（tp=8 时 39% 已缓解，但 8 核仍被三实例共享）。
   - 建议：可尝试 `thread_pool_size=4-5`（合计 12-15 线程）对比；多核机器上三实例才体现线性扩展；极端可绑核。

2. **系统态 %system ~84%**：**日志级别下调（warn）已落地但 %system 未降 → 日志写盘不是主因**，大头是网络 `recv/send` + 连接管理。
   - 建议：网络侧依赖 Nginx `sendfile`/`open_file_cache`（已部署）；连接级 `sendmsg` 批量。

3. **内存分配**：thread_local 复用 + 直出已把每请求分配压到最低（perf 显示非热点）；不要再引入全局分配器替换（对象池/SlabPool 实测中性或回归，已移除）。

4. **线程池 3 已验证收益显著**：吞吐 +8%~+112%（低并发档）、%wait -3.8pct、稳定性 +35%——tp=3 为当前三实例推荐配置（见 §8 对比）。

## 9. 复现方法

```bash
# 1. 生成高限流 + log_level=warn 配置并启动三实例（warn 日志归零根治写满磁盘；
#    thread_pool_size=3 已在 config/instance_808X.json 中，sed 生成时自动带上）
mkdir -p /tmp/bench_instances
for p in 8081 8082 8083; do
  sed -e 's/server.rate_limit.max_requests=100/server.rate_limit.max_requests=10000000/' \
      -e 's/server.log_level=info/server.log_level=warn/' \
      config/instance_${p}.json > /tmp/bench_instances/instance_${p}.json
  nohup ./webserver --port $p --config /tmp/bench_instances/instance_${p}.json > /dev/null 2>&1 &
done

# 2. 三实例并行压测（汇总脚本）
python3 tools/bench_3instances.py "/api/shops" 8 4 "1,8,16,32,64,128"

# 3. 最大并发（每实例 c，三路并行）
for p in 8081 8082 8083; do (wrk -t8 -c512 -d8s http://127.0.0.1:$p/api/shops > /tmp/mc.log 2>&1) & done; wait

# 4. 资源采样（60s 三路 + 分实例 pidstat）
for p in 8081 8082 8083; do (wrk -t4 -c128 -d60s http://127.0.0.1:$p/api/shops > /dev/null 2>&1) & done
for pid in <PID1> <PID2> <PID3>; do (pidstat -p $pid -u -r 5 12 > /tmp/res_$pid.txt 2>&1) & done; wait

# 5. 稳定性（3×60s @ 每实例 c=64，建议在 load 低时进行）
for i in 1 2 3; do
  for p in 8081 8082 8083; do (wrk -t4 -c64 -d60s http://127.0.0.1:$p/api/shops > /dev/null 2>&1) & done; wait
  redis-cli info stats | grep total_commands_processed   # 前后对比增量
done

# ⚠️ 压测后清理：kill 三实例进程；rm -f server_808*.log /tmp/bench_instances/*.json
```
