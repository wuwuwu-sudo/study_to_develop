# webserver 三实例性能测试报告（2026-08-18 · tp=3/3/3 + 批量读发 复测）

- **测试日期**：2026-08-18
- **工具**：wrk 4.2.0（~/.local/bin）+ pidstat / procfs（RSS/fd）+ redis-cli
- **服务器版本**：release 构建（C++17, epoll + **线程池 3/3/3 ×3 实例** + SQLite 连接池 16×3 + WAL）
- **本版优化**：**线程池批量唤醒**（任务数达线程数 notify_all 全员开工、少量任务 0.5ms 攒批兜底、空闲深度睡眠）、**批量读 + 批量发 + 超时兜底**（读 50ms/256KB 上限防读饥饿，整批响应累积 `send_buf` 一次 writev 批量发出）、**请求保护器（有界队列+熔断+高水位降级）**、**降级/熔断状态日志（按比例采样）**、**日志 500ms 批量落盘 + 满批立即落盘**；沿用 WAL、16 分片锁、字符串直出（方案 A）、thread_local 复用、延迟缩容、日志级别下调/抽样
- **架构**：三实例并行（8081 / 8082 / 8083），共享 Redis（L2）+ 共享 SQLite（WAL）
- **压测目标**：三实例合计 QPS、响应延迟、最大并发连接数、资源消耗、长时间稳定性、缓存分层
- **本次为 tp=3/3/3 复测**（各端口线程数改回 3，合计 9 线程匹配 8 核）+ 批量读发重新实现

## 7. 性能瓶颈与优化建议（当前版本，tp=3/3/3 + 批量读发）

1. **CPU 饱和（首要）**：8 逻辑核跑 3×3=9 worker 线程，%wait ~32.3%（历次最低）——**9 线程是 8 核三实例最优配置**，吞吐上限由 CPU 饱和决定。
   - 建议：保持 tp=3；多核机器上三实例才体现线性扩展；极端可绑核（`taskset`）。

2. **系统态 %system ~79%**：**网络 `recv/send` + 连接管理仍是大头**（批量发已优化 writev 次数，但连接建/拆与系统调用仍是主体）。
   - 建议：网络侧依赖 Nginx `sendfile`/`open_file_cache`（已部署）；进一步可 `sendmsg` 多缓冲批量或 `SO_REUSEPORT` 多 epoll。

3. **批量读发 + 批量唤醒 + tp=3 组合为本版最佳**：`/api/shops` 199.1k 创历史新高，`/api/dishes` +27%，%wait 最低。

4. **静态页 c=64/128 回落（101.7k/90.0k）**：批量发 `send_buf` 拼接对静态页（send_file 读入 body 后拼接拷贝）在高并发档有一定开销；静态页建议依赖 Nginx sendfile 直接服务。

## 9. 复现方法

```bash
# 1. 生成高限流 + log_level=warn 配置并启动三实例（tp=3/3/3 已在 config/instance_808X.json 中）
mkdir -p /tmp/bench_instances
for p in 8081 8082 8083; do
  sed -e 's/server.rate_limit.max_requests=100/server.rate_limit.max_requests=10000000/' \
      -e 's/server.log_level=info/server.log_level=warn/' \
      config/instance_${p}.json > /tmp/bench_instances/instance_${p}.json
  nohup ./webserver --port $p --config /tmp/bench_instances/instance_${p}.json > /dev/null 2>&1 &
done

# 2. 三实例并行压测（汇总脚本）
python3 tools/bench_3instances.py "/api/shops" 8 4 "1,8,16,32,64,128"
python3 tools/bench_3instances.py "/" 8 4 "1,8,16,32,64,128"
python3 tools/bench_3instances.py "/api/dishes?merchant_id=1" 8 4 "1,8,16,32,64,128"

# 3. 最大并发（每实例 c，三路并行；用 Python subprocess 避免 shell wait 挂起）
python3 - <<'EOF'
# （Popen 三路 wrk + proc.wait(timeout) 汇总）
EOF

# 4. 资源采样（60s 三路 + 分实例 pidstat）
for p in 8081 8082 8083; do (wrk -t4 -c128 -d60s http://127.0.0.1:$p/api/shops > /dev/null 2>&1) & done
for pid in <PID1> <PID2> <PID3>; do (pidstat -p $pid -u -r 5 12 > /tmp/res_$pid.txt 2>&1) & done; wait

# 5. 稳定性（3×60s @ 每实例 c=64，建议在 load 低时进行）
for i in 1 2 3; do
  for p in 8081 8082 8083; do (wrk -t4 -c64 -d60s http://127.0.0.1:$p/api/shops > /dev/null 2>&1) & done; wait
  redis-cli info stats | grep total_commands_processed   # 前后对比增量
done

# ⚠️ 压测后清理：kill 三实例进程；rm -f server_808*.log /tmp/bench_instances/*.json
```
